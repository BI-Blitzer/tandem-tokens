How it works

A digest-only contract

Claude turns a bulk request into a validated job spec; a local daemon drains it through Ollama; every worker output stays on disk. Claude reads only a compact (≤8 KB) digest — so the map phase runs for zero Claude tokens.

map

map

Chunk inputs, run a template per chunk, merge — bulk clean, extract, classify, summarize, or codegen over many rows.

g·t

gen_test

Generate N candidates, score each with a verifier, keep the best, feed survivors back — an autoresearch loop.

pipe

pipeline

Chained stages with per-stage filters — a cheap model triages, a bigger one cleans only the flagged rows.

vec

embed

Embed each item into a vector with a local model — build a RAG/search store without a per-document cloud bill.

Savings are map-phase only. A premium reduce/clean pass over the results still costs tokens — the win scales with keeping that pass small: review a digest and write a fix-up, don't re-read every row. Scoreboard also tracks GPU Wh, grid $, and optional CO₂.

Quickstart

Running in five steps

You need Python 3.11+ and Ollama. Everything else the CLI checks for you.

Install Ollama and pull your models

# https://ollama.com/download — then pull what you route to
ollama pull gemma2:9b
ollama pull qwen2.5-14b-instruct

Model routing lives in config/models.yaml — the single source of truth.

Install tandem-tokens

git clone https://github.com/BI-Blitzer/tandem-tokens
cd tandem-tokens
python -m pip install -e ".[dev]"

Installs two console scripts: ollamaq (the CLI) and ollamaq-mcp (the MCP server).

Check your setup

ollamaq doctor      # config + Ollama + model coverage
ollamaq recommend   # what fits your GPU vs. spills to CPU

Run the hybrid campaign (or any job) and score it

# VRAM-friendly order: summarize → pipeline → 14b map
ollamaq run jobs/uc3_summarize_docs.job.json
ollamaq run jobs/uc2_pipeline_support.job.json
ollamaq run jobs/uc1_map_clean_contacts.job.json
ollamaq score       # tokens, cloud $ avoided, GPU Wh / $ / CO₂

Large input? Add --stream. Edit config/energy.yaml for your grid $/kWh.

Wire Claude, Grok, or Codex (optional)

# Claude Code: .mcp.json in the repo
# Grok Build: .grok/config.toml  →  /mcps refresh
# Codex: clients/codex.config.toml → ~/.codex/config.toml
ollamaq daemon      # one per machine so queue_submit drains

Skills: /offload · /harvest · portable skills/hybrid · AGENTS.md for Codex.

Requirements & platforms

Runs where Ollama runs

What you need

  • Python 3.11+ and Ollama, plus the local models you route to.
  • ~16 GB VRAM to run 14B models fully on GPU; smaller models need less. ollamaq recommend tells you exactly what fits.
  • GPU detection covers NVIDIA (tested), AMD, and Apple Silicon — best-effort on the latter two; anything else falls back to size-only advice.

Tested on

Windows 11 and Linux run the full suite green in CI. macOS is portable Python — expected to work, not yet in CI.

Hooks & MCP

Usable from any MCP client

One standard stdio MCP server (optional Grok facade with hybrid_* aliases). The command is identical everywhere — only the client config format differs.

MCP toolpurpose
ollama_quickone-shot local generation, output capped (~2k tokens) so it never floods context.
queue_submitenqueue a batch job for the daemon; returns a job id.
queue_statusqueue state — counts, or one job's detail.
queue_digesta finished job's ≤8 KB digest.
recommend_modelsGPU-aware advice: which local models fit this machine vs. spill.
hybrid_scorecumulative scoreboard: tokens, cloud $ avoided, GPU Wh / $ / CO₂.
hybrid_energylive nvidia-smi power sample (watts / limit / temp).
hybrid_policywhen to offload vs. keep work in premium context.

Clients: Claude CodeClaude Desktop OpenAI CodexxAI GrokCursor — plus CLI, clients/ drop-ins, and /offload · /harvest · hybrid skill.

Security

One trust boundary, guarded

Verifier commands run arbitrary subprocesses

A job spec's verifier.cmd (gen_test) executes a local command — powerful, but it means submitting a spec is submitting code to run. From the CLI that's you on your own machine. Over MCP the server may be reachable by a less-trusted client, so verifier jobs are refused over MCP by default; set OLLAMAQ_MCP_ALLOW_VERIFIER=1 to allow them only if you trust the client. Don't expose the MCP server to an untrusted network.
