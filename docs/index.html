How it works

Claude turns a bulk request into a validated job spec, a local daemon drains it through Ollama, and every worker output stays on disk. Claude only ever reads a compact (≤8 KB) digest — so the map phase runs for zero Claude tokens. Three job modes:

modewhat it does
mapchunk inputs, run a template per chunk, merge — bulk clean / extract / classify / summarize / codegen.
gen_testgenerate N candidates, score each with a verifier, keep the best, feed survivors back — an autoresearch loop.
pipelinechained stages with per-stage filters — e.g. a cheap model triages, a bigger model cleans only the flagged rows.
embedembed each item's text into a vector via a local embedding model — build a RAG/search store without a per-document cloud embedding bill.

Savings are map-phase only. A Claude reduce/clean pass over the results still costs tokens — the win scales with keeping that pass small (review a digest and write a fix-up, not re-read every row).

Requirements

  • Python 3.11+ and Ollama, plus the local models you route to.
  • ~16 GB VRAM to run 14B models fully on GPU; smaller models need less. The ollamaq recommend command tells you exactly what fits vs. spills to CPU.
  • recommend detects NVIDIA (nvidia-smi, fully tested), AMD (rocm-smi) and Apple Silicon (unified memory) — best-effort on the latter two. Anything else falls back to size-only advice. The harness itself runs on whatever Ollama supports.

LLM platform hooks & MCP

One standard stdio MCP server, five tools, usable from any MCP client — the server command is identical everywhere; only the client config format differs.

MCP toolpurpose
ollama_quickone-shot local generation, output capped (~2k tokens) so it never floods context.
queue_submitenqueue a batch job for the daemon; returns a job id.
queue_statusqueue state — counts, or one job's detail.
queue_digesta finished job's ≤8 KB digest.
recommend_modelsGPU-aware advice: which local models fit this machine vs. spill.

Clients: Claude CodeClaude Desktop OpenAI CodexxAI Grok — plus the CLI and the /offload & /harvest skills.

Security

Verifier commands run arbitrary subprocesses.

A job spec's verifier.cmd (gen_test) executes a local command — powerful, but it means submitting a spec is submitting code to run. From the CLI that's you on your own machine. Over MCP the server may be reachable by a less-trusted client, so verifier jobs are refused over MCP by default; set OLLAMAQ_MCP_ALLOW_VERIFIER=1 to allow them only if you trust the client. Don't expose the MCP server to an untrusted network.

Install

git clone https://github.com/BI-Blitzer/tandem-tokens
cd tandem-tokens
python -m pip install -e ".[dev]"

ollamaq doctor                 # check config + Ollama + model coverage
ollamaq recommend              # what fits your GPU
ollamaq run examples/support_triage.job.json   # a real bulk job
ollamaq score                  # cumulative tokens run for $0, cloud spend avoided
